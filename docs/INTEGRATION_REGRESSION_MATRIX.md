## 使用方式
每次新增或修改功能時，先選出受影響列，完成靜態檢查與可執行測試後才允許合併。狀態「待測」不等於已通過。

## 本輪具體調整
- 強制要求每次變更前搜尋已存在的相同功能與相關版本，不只看正在修改的檔案。
- PR 描述必須列出「已有功能與依賴」及「整合影響分析」。
- 將跨系統回歸矩陣作為審查入口；任何受影響的舊系統都必須測試或明確標記未測。
- 不將 patch 文件的存在當作已整合到專案；必須核對最終完整檔案。

## 目前已知阻斷
1. 可用環境沒有 Godot 4 執行檔，故不能完成引擎解析／啟動／遊玩測試。
2. M1.3 舊 inventory 與 SurvivalInventory 尚未統一資料來源。
3. M1.3.1—M1.3.4 目前有分段 patch／ZIP 版本紀錄，需產生單一整合後基線並比對差異。
4. 動物死亡狀態與戰利品掉落物的持久化仍未實作或驗證。

## 合併條件
- 文件與索引互相連結。
- 審查者可從 PR 看出舊功能的影響範圍。
- 對所有受影響系統有測試結果；無法執行的測試需明確註明，不得標成通過。
- PR 的變更範圍合理，沒有未經檢查的二進位檔或衝突 patch。
