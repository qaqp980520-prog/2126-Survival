## 必做流程
- 每輪開始先核對最新 main、所有相關 PR／分支、CI 與 Notion 資產總目錄。
- 從最新 main 建分支；先看 diff，再測試，再合併。
- PR 必須寫明已有功能、依賴、測試證據、限制及回滾方式。
- 不把匯入、解析、runtime smoke、人工遊玩、GPU shader 編譯或 iPhone 測試混為一談。
- 失敗測試需保留原因與修正紀錄；過時 PR 應在內容被安全移植後關閉，不能把它們當成已合併。
- 合併後同步 `PROJECT_INDEX.md`、每日工作紀錄與 Notion 資產總目錄。

4. 動物死亡、掉落物與完整世界狀態持久化仍需後續實作。
