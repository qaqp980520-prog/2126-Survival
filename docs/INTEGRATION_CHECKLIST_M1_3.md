# M1.3 跨系統整合檢查清單｜2026-10-25

## 原則
新增功能必須與現有功能整合；不把獨立腳本存在視為整合完成。每次修改先檢查呼叫端、資料來源、存檔格式、場景節點與舊版相容性。

## 本輪整合風險
- [ ] M1.3 `scripts/world.gd` 與 `systems/SurvivalInventory.gd` 目前各自維護背包資料，尚未統一資料來源。
- [ ] `systems/SurvivalWorldBridge.gd` 尚未掛入既有世界場景，也未連接採礦、拾取、丟棄、HUD、角色控制器或存檔。
- [ ] M1.3.1 作物持久化 patch 與 M1.3.2 重複讀檔修補需要先整合成一份完整腳本，再進行測試；不能直接假設兩份 patch 疊加後可用。
- [ ] 作物標籤的父子節點改動要檢查 `_add_label` 的其他呼叫，避免改變固定世界標籤的生命週期。
- [ ] 存檔 v1/v2 相容性、錯誤資料、缺欄位及重複載入需要回歸測試。

## 建議測試順序
1. 在乾淨副本套用 M1.3.1、M1.3.2，確認 patch 能乾淨套用且無重複／衝突區塊。
2. Godot 4 專案解析與啟動。
3. 世界初始化、移動、採集、種植、成熟、採收。
4. 存檔、重新載入一次、連續載入兩次。
5. 舊 v1 存檔載入、新 v2 存檔往返。
6. 接入共用背包後，重測採礦、拾取、丟棄、重量與跳躍限制。
7. 每項修復後重跑受影響測試，最後做完整回歸。
