## 已確認／高度可信的問題
### A-001｜M1.3 世界存檔未保存世界狀態（高可信，功能缺口）
檔案：2126_Survival_World_Inventory_Persistence_M1_3/scripts/world.gd
- _save_game() 目前保存背包、遊戲日、體力、快捷欄、選取欄位及玩家位置。
- planted_crops（玩家種植中的作物）、crop_respawns（野生作物重生排程）、已生成掉落物／已擊敗動物等世界狀態沒有納入存檔。
- 重開遊戲會重新呼叫 _build_world()，因此採集過的野生作物、種植作物成熟狀態及世界掉落物不會依先前狀態還原。
- 建議：定義 world-state schema，序列化作物與重生排程；對不需要持久化的暫時掉落物明確寫入設計決策，並做保存／讀取往返測試。

### A-002｜M1.3 存檔載入未驗證版本與物品值（中高可信）
檔案：2126_Survival_World_Inventory_Persistence_M1_3/scripts/world.gd
- 存檔含 version，但 _load_game() 未檢查版本。
- 載入時只遍歷目前 inventory 已存在的鍵；未知鍵會被忽略，這對未來擴充可能造成資料遺失。
- int(saved_inventory.get(...)) 缺少明確的逐欄位 schema 驗證。
- 建議：驗證版本、數量型別與非負值；保留或明確遷移未知欄位；錯誤存檔需回報而非默默套用。

### A-003｜共用背包物品重量表不完整（已知限制）
檔案：systems/SurvivalInventory.gd
- 未登記的物品目前使用 ITEM_WEIGHTS.get(item_id, 0.0)，未知物品會被算成 0 kg。
- SurvivalWorldBridge 可接收任意 item ID，故上游傳入尚未定義重量的物品時可能低估負重。
- 建議：正式整合前補齊物品 registry；未知 ID 應拒絕、回報錯誤或採取明確預設，而非靜默視為零重量。

### A-004｜共用背包目前尚未接入 M1.3（狀態確認）
檔案：systems/SurvivalInventory.gd、systems/SurvivalWorldBridge.gd、M1.3 的 scripts/world.gd
- M1.3 仍自行維護 inventory、ITEM_WEIGHTS、負重計算與存檔；新 bridge 是獨立接口，沒有替換既有流程。
- 因此目前兩套模型不會自動同步，不能宣稱背包已整合。
- 建議：先選定單一資料來源，寫 adapter/migration，再做採集、丟棄、負重、存檔／讀檔回歸測試。

## 尚需進一步核對的風險
- 歷史 ZIP 中有每日合集與版本分支，部分 ZIP 內部根目錄名稱和 ZIP 檔名版本不同；需逐項核對是否為預期沿用，而不是錯誤封裝。
- 每個 Godot 原型的場景路徑、腳本引用、輸入映射、動態節點型別與執行期訊號尚未由 Godot 解析器驗證。
- 小遊戲的碰撞、計時、勝負流程與鍵盤操作尚未在引擎內測試。
- GitHub 已提交的近期小遊戲原始碼與本機 ZIP 原件是否逐位元一致，除非比對雜湊，不能推定相同。
